# 《废柴仙途》HD-2D 视觉重设计

> 一句话：**像素还是那些像素，光是新的。** 人物和地面保持清晰的像素画（密度翻倍），其余一切——纵深、虚化、灯火、光柱、浮尘、调色——按高清来做，叠成一幅“会呼吸的水墨立体画”。
>
> 代码：`src/fx/hd2d.js`（渲染模块）+ `src/art.js` 里的分层挂点。样张：`docs/hd2d_mock/`。出图 `node tools/hd2d_shots.js`，测帧 `node tools/hd2d_perf.js`。

## 0 现状与目标

| | 现在 | 目标 |
|---|---|---|
| 场景 | 200 像素宽的一张平面画，逐层直接叠 | 天 / 远 / 中 / 地 / 人物 / 前景六层，带视差、景深、空气透视 |
| 光 | 夜里一层正片叠底 + 抖动的圆斑 | 主光方向、轮廓光、平滑光晕、辉光、体积光、投影与地面反光，随昼夜和地图变 |
| 人物 | 1 倍密度、平涂 + 描边 | 2 倍密度，迎光收线提亮、背光压冷暗部，轮廓光跟场景主光走 |
| 界面 | 平色面板、20×20 的九宫格 | 3 倍密度九宫格（高光 / 内描线 / 角花）、卷轴木轴、宣纸纤维、投影与微光 |
| 兼容 | —— | `ART.*` 接口名与参数全部不变；关掉高清就是原来的画面 |

## 1 整体美术方向

### 1.1 色彩体系

- **三段色温**：暗部偏冷紫（`#2a1f52` 一系）、中间调保持原画固有色、亮部偏暖（`#fff3cf`）。原有 `hs()` 的明暗偏色规则保留，高清层在此之上再做一次整体调色。
- **每个场景一个主调**（`HD2D.profiles`）：用“柔光”混合罩一层主色，强度 0.10～0.18。洞府跟天色走（取当前天空的地平线色）；野林偏青绿、黑风岭偏橙红、古墓偏靛蓝、血煞偏绛红、剑冢偏冰蓝、魔渊偏紫、龙宫偏青、星墟偏靛紫、仙府偏金、混沌偏紫青。
- **语义色不动**：修为玉绿、战力珊瑚、灵石青、可操作金、危险朱（DESIGN §5.1）。高清层只给它们加同色微光，不改色相。
- **黑不用纯黑**：最暗处收在 `#08060e`～`#120f1c`，暗角用 `#080614`。

### 1.2 光照规则

1. **一个主光**：每个场景有且只有一个主光方向（左上 / 右上 / 正上 / 自下而上的地火）。洞府的主光是太阳或月亮，位置随昼夜移动；历练地图在配置里写死。
2. **轮廓光**：人物层朝主光那一侧的边缘，按主光颜色提亮 1 个高清像素（半个旧像素）。白天暖白、黄昏橙、夜里月蓝、血煞地图红。
3. **发光物必有光晕**：灯笼、窗、丹炉、阵法、灵宠觉醒、人物灵光——原来 `ART.glow` 画的抖动圆斑，高清模式下改成一盏平滑的灯（径向渐变，“滤色”混合，不会把人脸冲白）。人物身后的灵光画在人物**后面**。
4. **辉光**：画面里足够亮的部分（太阳、火、剑气、白色特效）向四周溢出。做法是缩小 → 自乘两次只留高光 → 再缩一半糊开 → 加回去。
5. **体积光**：太阳 / 月亮 / 天窗处向下散开一把光束，缓慢摆动、明暗呼吸。清晨和黄昏最强，正午最弱，夜里是很淡的月光。
6. **投影与反光**：脚底在同一条线上的场景（历练、对决、秘境），人物层整体压扁、按主光方向斜着投在地上；论道台、水系秘境这类光滑地面再加一层淡淡的倒影。
7. **夜色**：地面和人物一起以环境光正片叠底（保留色彩），上沿用渐变接进山色，不再有一条硬边；灯火在夜里放大、加亮。

### 1.3 景深规则

- **焦平面 = 地面层 + 人物层**：永远清晰，最近邻放大，一个像素都不糊。
- 天空微虚、远山全虚（缩到一半再双线性放大）、中景微虚、**前景最虚**且视差最大（洞府的前沿云海、以后的近景枝叶）。
- 3 档另有移轴：地面层上半截（远离镜头的部分）按竖向渐变稍稍虚化。
- 远景与中景之间垫一层空气透视（按地图的雾色做竖向渐变）。

### 1.3b 焦段（第五轮调焦，`HD2D.profiles[*].focus`）

第四轮的默认档读起来“只有主角是清楚的”：虚化近景盖住了下面三分之一、夜色把没灯的地方压成一片黑、辉光和光柱把石台罩成雾。现在每个场景配一个**焦段** `focus: [y0, y1]`（逻辑 y，不含 OY）——人物、建筑、平台站的那一带（洞府 72～150，历练 86～136，舞台 84～136）：

- 焦段里地面层与人物层逐像素清晰；辉光 / 体积光在焦段里压到三成（上下各羽化 10 像素）；
- 移轴（2 档起）只虚焦段上面的远处（洞府 26～70，历练 26～84，舞台 18～82），不再虚到屋檐和人头；
- 虚化近景改稀：不卷动的场景只在两角各 15% 的宽度里长几丛（中间七成留给主体），左上角的枝叶缩到三成宽；卷动的地图隔三差五一丛，高度不超过脚线以下那一条；不透明度 0.8～0.86；
- 夜色：光照图只比环境色再压一成（原来九成）；地形预染的环境色与光照图在 78～96 行互相渐变，不留亮度台阶；
- 洞府的软落影 0.34 → 0.07、调色 0.1 → 0.06、辉光 0.4 → 0.28；暗角中间一大块不压，只收四缘；高清下山岚淡到 0.3。
- 冒烟测试把它钉住：1.5 档洞府“门脸 + 石台”的亮度拉普拉斯方差 ÷ 0 档 ≥ 0.8（白天 / 黄昏 / 夜里；现在 0.81 / 0.86 / 1.46——夜里比原画面还清楚，因为不再整片压暗）。

### 1.4 像素密度与缩放

| 名称 | 尺寸 | 用在哪 |
|---|---|---|
| 逻辑像素 | 200 × (160～250) | 界面摆放用的坐标系，**不变** |
| 高清像素 | 逻辑像素的 1/2（400 宽） | 人物层、地面层的真实分辨率；轮廓光、收细的描边都是这个粒度 |
| 设备像素 | Pixel 7 上 1 逻辑像素 = 5 设备像素 | 3 档时光晕 / 粒子 / 暗角按这个粒度画，是真正平滑的 |

- 规则：**形体用高清像素，光用设备像素**。任何“画出来的东西”（人物、地形、图标）都对齐高清像素网格；任何“光”（光晕、辉光、光柱、暗角）都不对齐网格、要平滑。
- 旧精灵（1 倍密度）进场景时自动升 2 倍：Scale2x 把斜线和圆角磨顺（棋盘抖动不受影响），再补一遍体积明暗（§2.1）。新画的素材可以直接按 2 倍密度画，给画布标 `_hd = 2` 即可按逻辑尺寸落笔。
- 镜头：远层随一个很慢的正弦摇移（周期 9 秒 + 23 秒叠加，幅度 ±2 逻辑像素），越远跟得越多、前景反向；**地面与人物不动**，所以界面上的飘字、点击位置都不受影响。

### 1.5 第二轮加强（样张 v2）

第一轮的样张读起来像“加了一层滤镜”，第二轮把纵深和光做重：

- **夜色改成光照图**：先铺很深的蓝（环境色再向 `#0a103a` 压八成），再把每盏灯和它落在地上的椭圆光池加上去，整张正片叠底。没灯的地方真的暗，灯笼、石灯、山门、人物灵光各自照亮一小片。
- **虚化近景层**：镜头跟前的草叶、枝条、乱石（按地图换形状和颜色，洞府随季节换色），预先糊好一张，视差最大，历练时比地面卷得快。
- **移轴下放到 2 档**：地面层上半截先缩到四分之一再放大，叠在清晰的地面上，越远越虚。
- **软落影**：洞府这类脚底不在一条线上的场景，人物层整体向背光一侧落一层糊开的影子。白天人物灵光在地上也落一圈光。
- **光束加强、暗部抬紫**：体积光强度 ×1.7；最后用“变亮”混合把最暗处抬到 `#17122a`。
- **精灵重新打光**（`relight()`）：每一行里同一块颜色当成一段圆柱面——左侧三分之一处一条受光带、右缘转暗偏冷；宽的布面压斜向衣褶；深色头发加一道竖高光。这是程序打光，不是手工重画。
- **对话**：有立绘时背景画布整体虚化（CSS 模糊 2.4 像素）；立绘左右两缘各染一道轮廓光，颜色取自背景左右两半的亮色（火在哪边，哪边的脸就暖）；上方亮的一侧斜下来一把光束，外加几粒镜头前的大光斑。

### 2.1 场景小人

| | 现在 | HD-2D |
|---|---|---|
| 打坐像 | 32×36 | 64×72 高清像素（逻辑尺寸仍 32×36，`ART.dims` 不变） |
| 站姿 / 对决 | 24×37、48×40 | 48×74、96×80 |
| 明暗层次 | 固有色 + 一级暗部 + 描边 | 五级：轮廓光 / 高光线 / 固有色 / 冷暗部 / 描边（迎光一侧描边收细半个像素） |
| 动画 | 打坐呼吸 2 帧、站姿 2 帧、对决 6 帧 | 第一期沿用原帧；第二期补：打坐 4 帧呼吸 + 衣摆、行走 6 帧、施法 5 帧（起手 / 聚气 / 出手 / 收势 / 余韵）、受击后仰 |

体积明暗（`volume()`，只对人物类小精灵做，地形不做）：以左上为光——

- 距迎光边缘第 2 个高清像素、且是深色描边的：与里面的颜色对半 → 描边变细、变柔；
- 第 3、4 个：提亮 13% / 6% → 一线高光；
- 距背光边缘第 3、4 个：压暗 16% / 8% 并偏蓝 → 冷暗部。

### 2.2 半身像（48×48 → 96×96）

对话框、事件卡、人物页里的 `<img>`：`ART.portrait / portraitMe / portraitGen / portraitUnknown` 返回的画布在导出图片时给 2 倍密度的那张（界面本来就按 48 的整数倍写了宽高，版面不变）。第二期：主角与八位关键人物（老祖、慕、赵、楚天阔、雪、云、苏、叶）按 96×96 重画五官——眼睛 3 级高光、唇线、发丝分缕。

### 2.3 大立绘（96×128 → 192×256）

对话里的立绘画布（`.tk-pt`）每次重画后就地换成 2 倍密度 + 体积明暗（说话 / 不说话的明暗切换仍是界面原来的样式）。第二期：主角与关键人物按 192×256 重画，带 3 帧眨眼和发梢 / 衣带的 2 帧飘动。

## 5 渲染管线

### 5.1 接管方式（界面零改动）

`ART.setCtx(ctx)` 发现画布是 `#scene` 时调 `HD2D.attach(ctx)`：

1. 场景画布的后备尺寸改成 2 倍（400 × 2H）；界面读写 `cvs.height`、调 `ctx.setTransform(1,0,0,1,0,OY)` 时由垫片换算，界面仍以为自己在 200×H 上画。
2. `ctx.drawImage` 加垫片：标了 `_hd` 的高清画布按逻辑尺寸落笔；`ART` 缓存里的定稿小精灵自动换成 2 倍版（`WeakMap` 缓存，每张只算一次）。
3. `#scene` 上面叠一张呈现画布 `#sceneHD`（不接收点击）。原画布变成“人物层”。
4. 别处把场景画布当图片抠（过场拿洞府当底图）时，给它合成好的画面。

`ART.drawHome / drawAdventure / drawDuelStage / drawRealm` 内部用 `hdBegin → hdL(层名) → hdEnd` 把背景分别画进各层，画完把 `ctx` 还给人物层（此时人物层是空的、透明的）；之后界面照常往上画人物、建筑、特效。`ART.glow` 改记一盏灯，`ART.nightOverlay` 改记环境光与灯表。

### 5.2 每帧合成（`HD2D.present`，自己挂 requestAnimationFrame）

```
天空层 ──微虚──┐
日月大光晕      │
远景层 ──全虚──┤
空气透视（渐变）│
中景层 ──微虚──┤
地面层 ──清晰──┤→ 呈现画布
人物投影 / 反光 │   （1、2 档 400 宽，浏览器放大；3 档按设备像素）
身后灵光        │
人物层 ──清晰──┤
轮廓光          │
夜色正片叠底    │
前景层 ──最虚──┤
灯火（滤色）    │
光缓冲（1/4～1/5 分辨率：辉光 + 体积光，一次加回）
高清粒子、柔光调色、暗角、（3 档：颗粒、对比与饱和度）
```

Canvas 2D 里的几个做法：

- **虚化**：不用 `ctx.filter`（软件光栅下极慢），用“缩小再双线性放大”。
- **辉光**：不回读呈现画布（回读一次整张画布，软件光栅下要 60 多毫秒），直接把天空 / 地面 / 人物三层缩进小缓冲，`multiply` 自乘两次当阈值。
- **轮廓光**：人物层拷一份 → 用 `destination-out` 减去朝光源方向错开 1 个高清像素的自己 → 剩下的就是迎光边缘 → `source-in` 填主光色 → `lighter` 加回去。全层一次做完，3 次绘制。
- **投影**：人物层脚线以上的部分 `source-in` 填成墨色，用一个带切变的负纵向缩放矩阵画到脚线以下。
- **贴图预制**：光斑、光束扇面、暗角、颗粒、宣纸纤维都是启动后第一次用到时生成一次的小画布。

### 5.3 画质档与降级

| 档 | 名称 | 合成分辨率 | 内容 |
|---|---|---|---|
| 0 | 关 | —— | 原来的画面与代码路径，完全不接管 |
| 1 | 省 | 400 宽 | 分层、2 倍人物、轮廓光、灯火、夜色光照图、粒子（减半）、暗角 |
| 1.5 | 标准（**默认**） | 400 宽 | 1 档 + 景深、虚化近景、辉光、体积光、投影 / 软落影 / 反光、调色（内部是 2 档 + `HD2D.lite`，只少移轴那一遍） |
| 2 | 高 | 400 宽 | 1.5 档 + 移轴 |
| 3 | 极致 | 设备像素（Pixel 7：1000 宽） | 2 档 + 平滑的光与粒子、颗粒、对比 / 饱和度微调；可选色差（`HD2D.opts.ca`） |

- 设置：`HD2D.setQuality(0 | 1 | 1.5 | 2 | 3 | 'auto')`，记在 `localStorage.xm_hd`；网址带 `?hd=N` 可临时指定。单项开关 `HD2D.opts.{dof, bloom, rays, parts, grade, cam, rim, shadow, upres, skin, ca}`。
- 默认：1.5 档；核数 ≤ 2 或内存 ≤ 1G 的机器 1 档；自动化测试（`navigator.webdriver`）默认 0 档——无头浏览器没有 GPU，多出来的每帧开销会挪动 jitter_check / cine_test / story_ui 里按毫秒掐点的用例（章末卡弹出的时机、【跳过】0.45 秒等）；高清这条路由 `tools/hd2d_shots.js`、`tools/hd2d_perf.js`、`tools/hd2d_smoke.js` 用 `?hd=N` 显式覆盖。
- **自动降级**（`HD2D.auto`）：每 150 帧看一次，超过六成的帧间隔大于 26 毫秒就降一级：先把合成改成隔帧（30 帧，`HD2D.half`），再降档，最低降到 `HD2D.minQ`（默认 0 = 退回原画面）。只降不升，免得来回跳。
- 对话 / 过场盖住整屏时不合成场景；弹窗压着时六帧合成一次。

### 5.4 性能预算与实测

预算（中端机、60 帧）：界面自己画场景 ≤ 4ms，合成 ≤ 4ms，留 8ms 给浏览器。

实测（`node tools/hd2d_perf.js 4`：Pixel 7 视口、CPU 4× 节流、**无头 Chromium 软件光栅，没有 GPU**——比真机悲观，主要看各档的相对开销）：

| 档 | 合成画布 | 洞府 帧间隔 均值 | 战斗 帧间隔 均值 |
|---|---|---|---|
| 0 | 原画布 200 宽 | 16.7 ms | 17.0 ms |
| 1 | 400×454 | 25.4 ms | 19.5 ms |
| 1.5（默认） | 400×454 | **47.6 ms** | 37.2 ms |
| 2 | 400×454 | 50.2 ms | 38.6 ms |
| 3 | 1000×1135 | 237 ms | 192 ms |

（单独跑测帧工具三次取中位数，机器负载 1.2～1.7。三次里 1.5 档洞府是 46.5 / 47.6 / 49.0，2 档是 45.8 / 50.2 / 51.1——两档的差别比测量噪声小；p95 都是 66.7 ms，即偶尔拖到四个刷新周期。“合成的 JS 耗时”1.5 档约 7 ms，软件光栅真正的开销在随后的上屏里。）

不节流时 0～2 档都是 16.7 ms（60 帧），3 档 37～50 ms。

为了进预算做的事：辉光不回读呈现画布（回读一次整张画布要 60 多毫秒），改成把三层缩进小缓冲；体积光画进同一张四分之一分辨率的光缓冲；天 / 远 / 中 / 前景四层只用 1 倍密度；移轴和虚化近景只画有内容的那一条，不画整屏。

结论：默认档在“4× 节流 + 没有 GPU”这个最坏情况下洞府 47.6 ms（约 21 帧）、战斗 37 ms，在 50 ms 的预算内但余量不大；再慢的机器自动降级会先切到隔帧合成、再降到 1 档（25 ms）。有 GPU 光栅的真机上这些绘制都是贴图四边形，预期 1～2 档满帧；3 档要真机确认后再决定是否开放给玩家。**真机数据还没有**，列在 §7 的待办里。

```js
HD2D.cam({ z, x, y, ms, hold })       // 镜头推近：z 倍数（1.06 左右），(x, y) 焦点（逻辑坐标，y 含 OY），ms 推过去的时间，hold 停多久后自己退回；HD2D.cam() 退回
HD2D.camAt(x, y)                      // 推近之后这个逻辑坐标落在哪（飘字、点击判定用）→ { x, y, z }
HD2D.stageRain                        // true：对话舞台的雨由气氛层画（远 / 中 / 近三层），界面那层平的雨不用画；雨的大小给 stageFx 返回对象的 o.rain = 'rain' | 'storm' | ''
ART.tachieHD(id, mood, fx, alt) / ART.tachieMeHD(look, realm, mood, fx)   // 192×256 的 2 倍密度立绘（有重画稿给重画稿）
```

art.js 里新画 2 倍密度素材的约定：画布标 `c._hd = 2` → 场景里按逻辑尺寸落笔；大张的静态底图标 `c._hdOK = 1` → 允许自动升 2 倍（默认只升 160×160 以内的小精灵）。

## 9 已知的不足（如实）

- 背景的远 / 中景仍是 1 倍密度的原画（反正是虚的）；地面是“原画升 2 倍”，没有按 2 倍密度重画。人物里主角（打坐 / 站姿 / 对决六帧）、人形敌人、老祖（小人 / 半身像 / 立绘）、全部灵宠、野狼与五种小怪是重画稿；首领和其余人物的半身像 / 立绘还是通用机制（§2.0）。
- 界面里直接用方块画的东西（阵圈、吐纳环、粒子、进度条）还是 1 倍密度。
- 洞府场景里脚底不在一条线上，所以没有投影（建筑、灵宠各有各的地面高度）；要做得给每个精灵报脚底坐标（§6 第 3 条的延伸）。
- 帧率只在无头 Chromium（软件光栅）下量过，真机 GPU 下的数字没有。
- 物品 / 功法 / 灵宠卡这些 `<img>` 小图标还是 1 倍（§6-9，第三期）；`HD2D.cam` 还没有界面调用方。
- 焦段清晰度那一项白天只比 0.8 的线高一点（0.81）：2 倍密度稿把描边收细、把台阶磨顺，这个量法本身就会掉一成左右（所有后处理都关掉是 0.87～0.95）。
- `tools/cine_test.js` 里“【跳过】0.45 秒内结束”几项在本机负载高时会偶发超时，关掉高清跑也一样，和这次改动无关。
