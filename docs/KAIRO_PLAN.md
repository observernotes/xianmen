## 1. 诊断：现在哪里违背了开罗的做法

依据：2.1.0 代码、`tools/onboard.js` 跑出的前 13 分钟（截图在 `scratchpad/kairo/auto/`，两张对照图存在 `docs/kairo_mock/_scene_ref.png`、`_before_me.png`）。

1. **没有“路径”。** `L.CHAPTERS` 里明明有九章主线，但玩家只在札记那一行小字里见到当前一条小任务；没有任何地方画出“九章、你在第几章、这一章做完会怎样”。开罗的做法是目标和进度永远摆在主画面上。
2. **时间不等人。** `src/ui/boot.js` 的 `frame()`：只要没开弹窗，时间就按 6 秒一周天走，老祖气泡、横幅、飘字都不停表。三年之约是第 36 周天＝纯计时 3.6 分钟。玩家读两条气泡，一年就没了。
3. **年份失真。** 筑基后一周天 = 1.6 年（`REALMS[].mpt`），第 10 分钟主画面已经写着“第 19 年、39 岁”。日历（四季按周天 % 12）和年份（按 mpt）是两套钟，玩家没法建立时间感。
4. **在外面还被打断。** 历练途中照样冒访客飘字、解锁横幅、老祖气泡、换季提示（`onTick` 里除了少数几项都不看 `st.exp`）。
5. **对话框驱动。** `guide.js` 登记了 55 段讲解，另有约 30 种气泡、30 种横幅，前 10 分钟阻塞讲解 14 段。每一段都是“老祖说一句 → 高亮 → 你点”。玩家学到的是“跟着点”，不是“我为什么点”。
6. **核心入口被藏。** 2.1 为了减负把没开的入口全部隐藏：第 10 分钟底栏只有 历练 / 洞府 / 人物 三格；法宝和功法在 人物 → 一行折叠小字“详情：天赋、法宝功法”里。法宝是自动穿上的，玩家从头到尾没见过“装备栏”。
7. **做完没有总结。** 历练结算只报这一趟拿了什么，不报“战力 86 → 104”“约战胜算 62% → 71%”；没有年末总结；升级建筑后只有一行飘字。
8. **数字不成对。** 主画面有战力、修炼、灵石三个数，但没有“目标是多少”。开罗的数字永远是“现在 / 要求”。
9. **菜单是文章。** 面板里是整句说明（“布着聚灵阵：修炼 ×1.85。筑基后期能换别的阵法。”），人物页一个大按钮叫“每项数值怎么来、怎么提升”。应该是图标 + 数字 + 一个按钮。
10. **解锁没有仪式也没有落点。** 新系统是“横幅一闪 + 老祖一段话”，说完玩家不知道入口在哪一格，因为入口本身是刚冒出来的。

一句话：**玩家没有地图，表又一直在走，于是只能跟着弹出来的话点；点完没有结算，所以不知道自己什么情况。**

### 2.2 玩家任何时刻怎么知道“我在哪、下一站是什么”

三处，由近到远：

1. **主画面目标卡**（常驻，示意图 `01_main.png` 下半部）
   - 第一行：`第 N 章` 标签 + 本章目标（≤ 10 字）。
   - 第二行：进度条，文字固定为“现值 → 目标值”（例：`胜算 62% → 目标 80%`）。
   - 第三行：**下一步**，一句 ≤ 12 字 + 【去 ▸】按钮。点【去】= 打开对应面板并给那个控件套一圈金框（复用 `guide.js` 的聚光圈，不带文字、不停表、点别处就消失）。
   - “下一步”只有一条，按这个顺序取第一条成立的：① 修为圆满 → “可以突破了”；② 有未处理的新法宝 / 新功法 → “装备里有新东西”；③ 最近解锁但没掌握的系统的小目标（`L.onbGoal`）；④ 本章札记第一条小任务（`L.questView(st).first`）；⑤ 大节点 ≤ 6 月且胜算低于目标 → 锦囊第一条（`pactTips()[0]`）；⑥ 兜底“去历练”。
2. **时间条**（主画面顶部第二行，`01_main.png`）：本章是一条 36 格（第一章）或 12 格（之后每年一条）的格子，过去的月是绿的，当前月发亮，大节点是红格并在右上角写“三年之约 还有 14 月”。
3. **【仙途】→ 路径**（`02_menu_path.png`）：九章竖排，已过的打勾、当前章展开（目标、两条进度、已开系统的图标、还没开的画“?”）、之后的章只有章名和一句话。第二章起的系统只露数量不露名字（留悬念，也不提前灌名词）。

### 2.3 章与章之间怎么过渡

每章一张**章末结算**（阻塞，属于 §5.1 清单里允许的大事）：

- 上半：“第一章 废柴 · 完”，本章用了多少月、战力从多少到多少、历练多少趟、最好评价。
- 下半：“第二章 入宗”，目标一句话，“这一章会开 6 样新东西”（6 个“?”格），奖励（原 `main.rw`）。
- 一个按钮【开始第二章 ▸】。之后目标卡换成新一章。

## 3. 【P0-2】时间流逝

### 3.1 单位：只留一个“月”

- 界面上原来的“周天”全部叫**月**；3 月一季，12 月一年。日历年 = `floor(st.tick / 12) + 1`，和四季（本来就是按 tick 走的）对上。“三年之约”就是字面上的 36 个月。
- `st.year`（按 `mpt` 累加的那个）**不再显示**。年龄 / 寿元改成“寿元还够 N 月”= `(L.lifespan(st) - p.age) / (REALMS[r].mpt × L.ageRate(st))`，够 120 月以上只显示“寿元足”，60 月以内变红。玩家只需要一个钟。
- 逻辑层的 tick 不改名、不改数值；只是界面换词。`src/ui/core.js` 加 `const UNIT = '月'`，所有界面字符串里的“周天”换成它（P0 先换主画面、历练、结算、目标卡；P1 全量替换，`grep -c 周天 src/ui src/logic` 归零——逻辑层里给界面用的文案也算）。

### 3.2 时钟三态

| 态 | 什么时候 | ×1 时一月多久 | 允许出现什么 |
|---|---|---|---|
| **停** | 任何面板 / 弹层开着；聚光引导中；秘境里；**以及下面的“自动停”** | 不走 | 当前这张面板 |
| **打坐**（在洞府、没安排） | 默认 | **15 秒**（第一世）；转世后 8 秒 | 一季最多一次打断（§3.3）；一行传讯；入口闪烁 |
| **在外**（历练 / 闭关 / 特训 / 讲道） | 出发到归来 | 历练 **8 秒**，闭关类 **3 秒**；转世后各减半 | **什么都不弹**。只有这一趟自己的途中遭遇（已有，一趟最多一次）。画面是历练场景，每过一月给一拍：打一下 / 捡一下，左下角累计“灵石 +90 草 +3”（`07_exp_travel.png`） |

- 速度键只留 **×1 / ×2 / 暂停** 三档（`SPEEDS = [1, 2, 0]`），第一世金丹前不出 ×2 以上的提示。
- **自动停**（时间停住，直到玩家处理；不是弹窗，是主画面上那个入口闪 + 目标卡“下一步”换成它）：① 修为圆满可以突破；② 大节点前 1 月的备战卡（§3.3）；③ 历练 / 闭关归来的结算；④ 年报；⑤ 寿元第一次变红。
- **空转提醒**（不停表）：在洞府连续打坐满 3 月、没负伤、历练可去 → 【历练】格闪金框，传讯行写“闲了 3 月”。只此一种提醒，不出老祖。

### 3.3 什么时候允许打断

1. **在外：零打断。** `onTick` 里凡是 `st.exp || st.retreat` 时产生的 访客 / 换季 / 大势 / 拍卖开槌 / 新秀出世 / 解锁 / 掌握 / 宿敌消息，一律进**纸鹤**（消息匣，主画面右上角图标 + 数字）。归来结算最后一行汇总“你不在时：入秋了 · 有人来访（等你 6 月）”（`05_exp_result.png`）。
2. **打坐：一季一次。** 两次“主动打断”（解锁卡、事件抉择、老祖气泡）之间至少隔 3 月，且只在月初、玩家没开面板时出。排队顺序：解锁卡 > 事件 > 气泡；排不上的进纸鹤，不丢。
3. **访客不再倒计时催人。** 访客进纸鹤后，等待期从“你下次回到洞府”起算 6 月（`st.visitor.left` 在 `st.exp || st.retreat` 时不减）。点纸鹤里那一条才见人。
4. **大节点（三年之约、每年论道、九宗会武、天剑来犯、新秀逼战）提前四次预告，全部不阻塞，最后一次停表：**
   - 时间条上那一格从头就是红的，右上角常驻“还有 N 月”。
   - 还有 12 / 6 / 3 月：传讯行一句 + 目标卡进度条闪一下（“三年之约 还有 6 月 · 胜算 62%”）。年报里“明年”一栏也写。
   - 还有 1 月：**备战卡**（自动停）。内容：对手头像与战力、你的战力、胜算条、最多三条锦囊（每条“做什么 → 胜算变成多少”+【去】），两个按钮【再准备一下】（关卡片，时间仍停在这个月初，直到玩家自己点继续）/【就这样上】。
   - 若此时在外：强制在节点前 1 月归来（出发页就写“约战前会赶回来”；出发时若 `left < 行程`，按钮改成“来不及了：还有 N 月”禁用）。
5. **解锁卡节流：** 两张解锁卡之间 ≥ 8 月且 ≥ 6 分钟真实时间（子项 ≥ 4 月，子项不出卡，只在入口上挂“新”角标 + 传讯行一句）。

### 3.4 第一世 5～6 小时：逐章预算

不改各境界修为需求和 tick 骨架（guided 中位数约 618 月）。5 小时从三处来：打坐的月变慢（6 → 15 秒）；在外的月有演出（8 秒）；**每一个决定都停表**（现在是表走着、话压着）。

估算口径：一年 12 月 ≈ 2 趟历练（10 月 ×8 秒 = 80 秒看 + 每趟 30 秒选 + 25 秒结算）+ 2 月打坐（30 秒）+ 年报（25 秒）+ 一届论道（备战 + 对决 80 秒）+ 一件纸鹤里的事（30 秒）+ 花钱 / 换装 / 炼丹 / 交任务（90 秒）≈ **6.4 分钟 / 年 ≈ 32 秒 / 月**。

| 序 | 0 | 3 | 0:03 | — | — | — |
| 一 炼气 | 36 | 25 | 0:28 | 8～9 | 12 | 5 样 / ≥ 4 分钟（见 §5.4 脚本） |
| 二 筑基 | 38 | 26 | 0:54 | 8 | 13 | 7 样 / ≥ 3.5 分钟（其中 3 样是子项） |
| 三 金丹 | 62 | 36 | 1:30 | 12 | 21 | 6 样 / ≥ 6 分钟 |
| 四 元婴 | 75 | 42 | 2:12 | 15 | 25 | 7 样 / ≥ 6 分钟 |
| 五 化神 | 75 | 40 | 2:52 | 15 | 25 | 6 样 / ≥ 6 分钟 |
| 六 炼虚 | 75 | 38 | 3:30 | 15 | 25 | 0 |

## 7. 文案规则

| 位置 | 上限 | 写法 |
|---|---|---|
| 底栏格名、分页名、按钮 | 2～3 字（按钮可加价格数字） | 动词或名词，不带“前往”“查看” |
| 行内名字 | ≤ 6 字 | 超了用小号字缩一行，不换行 |
| 行内说明 | 0 字——换成 `图标 + 数字 + 单位` | `修炼 +12/月`、`战力 ▲ +41`、`12 月回本` |
| 小卡（点图标格出来的） | ≤ 40 字 | 一句“它是什么”+ 一句“去哪用” |
| “?” 一句话 | ≤ 30 字 | |
| 目标卡三行 | 合计 ≤ 40 字 | 目标 ≤ 10 字；下一步 ≤ 12 字 |
| 传讯行 | ≤ 20 字 | `月份 + 事 + 数字` |
| 老祖一句 | ≤ 20 字，一个数字 | 口语，不出现两个系统名 |
| 解锁卡 | ≤ 30 字 | 名字 + 给你什么（一个数）+ 入口路径 |
| 结算卡 | ≤ 40 字（不含名字数字） | |
| 面板第一屏 | ≤ 60 字（不含名字数字） | |

统一用词：月（不说周天）、战力、修炼 / 月、灵石 / 月、胜算、还有 N 月、▲ / ▼。一个概念只有一个名字（“法宝”是东西，“装备”是那一格菜单；不再出现“换上与熔炼”“对比卡”这类系统自称）。
改成图标的：四季（`ART.season`）、五行（`ART.elems`）、品阶（底框颜色）、评价（印章）、锁（`lock`）、新（`ART.newBadge`）、目标（`goal`）、消息（`mail`）、涨跌（▲▼ 颜色）。
事件、对话、图鉴里的故事文字不在此限（那是内容，不是菜单）。

实施：`tools/onboard.js` 已经在数各面板字数，把上表做成断言；逐面板收字时以它为准。

## 10. 变强页重做（取代 `showGrowth` 的“数值拆解”长表）

用户原话：**“现在能力提升那个引导页我非常不满意，内容太多太杂，根本不知道怎么办。”**

示意图：`docs/kairo_mock/growth.html` → `g1_goal.png`（目标页）、`g2_stat.png`（某个数 + 明细 + 小卡）、`g3_stuck.png`（卡住时）、`g0_all.png`（三张并排）。`node tools/growth_shots.js` 重新生成并顺带量字数。

### 10.1 诊断（实测，第一章中段，Pixel 7）

| | 现在的 `showGrowth` | §7 的上限 |
|---|---|---|
| 内容高度 | 2674 px（一屏 637，**4.2 屏**） | 一屏说完 |

它回答的是“这个数是怎么乘出来的”，而玩家点进来想问的是“**我现在做哪一件事最划算**”。另外同一个问题有三处在答、口径还不一样：目标卡“下一步”（`goalNext0` 的固定次序）、问老祖（`askList` 14 类候选按写死的次序取前三）、变强页（按公式次序罗列）。

### 10.2 这一页只回答一个问题

> **“离眼下的目标还差多少？做哪 1～3 件事最划算，做了涨多少？”**

规则四条：

1. **一个数、一条杠、三张牌。** 第一屏 = 头（目标 + 现在的数 + 目标线）＋ 老祖一句 ＋ ≤ 3 张动作卡。不滚动就看完。
2. **每张牌一个大数字。** 只有四种写法：`▲9% 胜算`、`+2/月`、`丙 → 甲`、`还差 8`。没有说明文字。
3. **一张牌一个按钮**，能当场做完的就当场做（换上 / 强化 / 升级 / 服下），做完本页原地重排，头上的数跳字。
4. **拆解表降级成“明细”**：默认合着，放在最底下；展开也只是 `图标 + 名字 + 条 + ×倍数`，一行一项、没有按钮没有说明，点一行才出 ≤ 40 字的小卡。

### 10.5 一套建议来源：`L.advise`

**三处合成一处。** 目标卡“下一步”、老祖头像、变强页都读同一个排好序的列表；不再有三套候选、三种次序。

- **目标卡**：`下一步` = `L.advise(st).acts[0]` 的名字；【去】直接执行它的 `go`（不经过变强页）。点目标卡的进度条 = 打开变强页 `goal`。
- **老祖头像**（`#guideAv`）：点它 = 打开变强页 `goal`。`showAsk` 这张面板删掉；老祖的口吻留在头下面那一句里。头像上的“！”改成：`acts[0]` 换了一条新的、且玩家还没看过时亮。
- **变强页**：`acts` 前三条。
- 空转提醒（S04 / S05 / S07 气泡）、备战卡的“还能做什么”、结算卡的“带木系来：预计 甲”【去换】，文字都取自同一条 `act`（`act.say`），不再各写各的。
- 不是“变强”的事（访客、交任务、拜师、拍卖、行情、天下大势）不进这一页：它们已经有纸鹤和入口上的“新 / 数字”角标（§5.2），`askList` 里对应的条目删掉。

### 10.6 怎么排（玩家能猜到的次序）

1. **必须先做的**置顶：去突破、疗伤、有待换上的新法宝。
2. 其余按“对当前页签那个数的涨幅”从大到小；`goal` 页签统一折成“离目标线近了多少”（胜算百分点 / 评价档 / 提前月数占剩余月数的比）。
3. 涨幅相近（差 < 20%）时：不花钱的 > 当场能做的 > 要出门的。
4. 涨幅不到门槛的不出（胜算 < 3 点、战力 < 3%、修炼 < 5%、早 < 1 月）。
5. 买不起 / 料不够的**不占前两张**；整个列表里最多留 1 张“还差”牌，取“差得最少、涨得最多”的那条，放第三张。
6. 同一类只出一张（强化只出涨得最多的那一槽；升级只出最值的那一项）。

### 10.9 验收

- 第一屏（Pixel 7 与 360×640）：汉字 ≤ 60、按钮 ≤ 6（页签不算）、没有 < 14px 的字、不滚动能看到头和全部动作卡、红色按钮恰好 1 个。（现状 690 字 / 14 按钮 / 4.2 屏。）
- 每张动作卡：恰好 1 个大数字、1 个按钮；名字 ≤ 8 字；没有句子。
- `instant` 的牌点一下：留在本页，头上的数在 300ms 内跳到新值，列表重排，飘字一次。
- 同一时刻：目标卡“下一步”、老祖那一句、变强页第一张牌说的是**同一件事**（`guide_test` 断言 `id` 相同）。
- 第一章抽 6 个时刻（第 2 / 8 / 14 / 20 / 27 / 34 月，guided 机器人）：`acts` 非空；第一张做完后目标数确实变好（`L.adviseDo` 后重算，涨幅与牌上写的差 ≤ 1 个显示单位）。
