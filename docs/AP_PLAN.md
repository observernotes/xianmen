# 《废柴仙途》行动点制与季度回合（AP_PLAN v1）

> 范围：**时间怎么走、历练与修炼怎么花、剧情什么时候播、主线靠什么行动推进**。玩法系统一个不加、一个不删。
> 本文取代 `docs/KAIRO_PLAN.md` 的 §3（时间流逝）全部、§5.1 第 9 条（解锁卡节流）、§5.4（前 30 分钟脚本的时间列），以及 `docs/STORY_PLAN.md` §0 原则 3 和 §1.2 里“只在洞府播 / 一季最多一场 / 一个月补一场”三条。KAIRO_PLAN 其余章节（路径、五格底栏、面板版式、目标卡、结算卡）继续有效。
> 用户已拍板“直接改、直接做完”，所以本文里的取舍都已定死，没有留给用户的问题。拿不准的数值给了初值、校准目标和校准顺序。
> 实施者读本文即可开工。实施拆分在 §9，接口在 §10。

## 0. 一页纸

**问题。** 时间按真实秒数流动，历练一走几个月，在外期间不打断；剧情又叠了“一次一段、最小间隔、解锁卡真实时间节流”。结果是：第三年打完三年之约，对应的戏第五年才出来。

**答案。** 时间不再自己走。**一回合 = 一季**，每季 3 点行动点；历练、闭关都是花点、当场结算；点【下一季】才过三个月。剧情不再排队等空档：**哪件事结算完，它的戏当场接着播，播完才回主界面。**

| 项 | 定案 |
|---|---|
| 回合单位 | **季**（3 个月）。一年 4 回合 |
| 每季行动点 | **3 点**，固定，不成长 |
| 底层时钟 | `st.tick` **仍按月计**，一回合推进 3 个 tick |
| 历练 | 2 点，当场打完整趟（回合战和翻牌都保留）。没有“在外”这个状态 |
| 闭关 | 2 点，当场得修为 |
| 修为 | 季末自然涨 3 个月 + 行动（打坐 1 点、闭关 2 点、斩妖感悟） |
| 一周目 | 约 **165 季**（约 41 年），每季约 2 分钟（含剧情），合计约 **5 小时 30 分** |
| 三年之约 | 仍是第 36 月 = **第 12 季末** |
| 剧情 | 关键事件到对应剧情的延迟 = **0 个行动**；闲戏、访客、解锁卡只在季初、季末两个时点出 |
| 速度档 | 删除。原速度键的位置换成【下一季 ▸】 |

**三条原则。**

1. **时间是玩家按出来的。** 不点【下一季】，日历不动。任何界面都不会在玩家没操作时推进时间。
2. **事和戏之间不隔任何东西。** 一场仗的结算卡关掉以后，下一张出来的一定是这场仗的戏。
3. **深度不加复杂度。** 只多一个量（行动点），同时删掉四个量（速度档、三态时钟、吐纳环、连续历练）和“在外”状态。玩家要记的规则只有一句：**大事 2 点，小事 1 点，管家务不花点。**

## 1. 回合单位为什么是季

### 1.1 三个候选

| 单位 | 一周目回合数 | 每回合真实时间 | 问题 |
|---|---|---|---|
| 月 | 约 500 | 约 35 秒 | 一个月要么只做一件事（等于把“时间流逝”换成“连点下个月”），要么做好几件事（一年历练 12 趟以上，全套数值重做）。季初季末的事件每 35 秒来一次，照样扎堆 |
| **季** | **约 165** | **约 2 分钟** | 无。一季 = 一趟历练 + 一件小事 + 管一轮家务，正好一屏 |
| 年 | 约 41 | 约 8 分钟 | 一回合太长，记不住这一年干了什么；三年之约只有 3 回合，第一章没法教东西 |

### 1.2 选季的四条理由

1. **现成的历法就是按季切的。** `L.seasonOf(tick)` 把每年的第 1～3 月算春、4～6 夏、7～9 秋、10～12 冬；四季、换季加成、秘境令（每年夏季）、年历都按它走。回合从季界（`tick % 3 === 0`）开始，推的正好是一整季的三个月，日历和回合天然对齐，不用再造一套钟。注意：回合进行中“本季”要取 `L.seasonOf(st.tick + 1)`（`st.tick` 停在上一季的最后一个月）。
2. **行动密度和现在接近，数值不用推倒。** 现在一趟历练 4～6 个月、闭关 4 个月，第一章 36 个月能做 8～9 件大事。改成一季一件大事后，第一章是 12 季、约 12 件大事，只多了三成多（校准见 §3.5）。按月做回合，大事会翻成 4 倍。
3. **事件有地方放。** 每季只有季初、季末两个固定时点能出非关键事件。165 季 × 2 个时点，足够把访客、闲戏、解锁卡摊开，每季最多各一件（§4.4）。
4. **“三年之约”还是三年。** 第 36 月 = 第 12 季末。论道每年一届 = 每 4 季一届。故事里的时间词一个不用改。

### 1.3 底层 `st.tick` 保留按月

**定案：`st.tick` 不改含义（1 tick = 1 月），一回合由 `L.seasonEnd(st)` 连推 3 个 tick。** 不改成按季计。

| | 保留按月（选这个） | 改成按季 |
|---|---|---|
| 以月计的常量 | 全部不动：`PACT_TICK 36`、`TOUR_EVERY 12`、`MEET_EVERY 24`、`RIVAL_SLOPE`、`REALMS[].mpt`、增益时长、作物生长、行情 6 月、拍卖 6 月、访客 6 月、新秀、徒弟、俸禄、换阵 3 月…… | 一百多处常量和文案要除以 3，除不尽的（4 月、5 月、8 月）要一个个重新定 |
| 旧存档 | 存档里所有时间戳（`st.tick`、`flags.war`、`sect.joined`、`story.beat`、`onb.at`……）原样可用，只需把 tick 补齐到季界 | 每个时间戳都要换算，漏一个就是一个错位的事件 |
| 每月的结算逻辑 | `L.tick` 里的每月结算（作物、丹毒、灵宠、行情、宿敌）原样连跑 3 次 | 每个模块的“每月”公式都要改成“每季” |
| 代价 | 一季里跑 3 次 `L.tick`，三次的产出要合并成一张季末卡（§2.5） | — |

约束：**回合之间 `st.tick % 3 === 0` 恒成立**（季界）。所有固定日子的大事（约战 36、论道 12k、会武 18 + 24k）本来就是 3 的倍数；天剑来犯的日子 `st.flags.war` 排的时候向上取到 3 的倍数。

### 1.4 历法与以月计的东西怎么换算

| 东西 | 底层 | 界面上怎么写 |
|---|---|---|
| 日期 | `st.tick` | `第 N 年 · 春 / 夏 / 秋 / 冬`。不再显示月份 |
| 四季与换季加成 | 不变 | 不变（每回合正好换一季） |
| 三年之约 | 第 36 月 | “还有 N 季”，N = `ceil(left / 3)`；最后一季写“本季末” |
| 天骄论道 | 每 12 月 | 每年冬季末（年报之后）。“还有 N 季” |
| 九宗会武 | 每 24 月，第 18 月 | 隔年夏季末 |
| 年报 | 每 12 月 | 冬季的季末卡就是年报（不另出一张） |
| 寿元 | 每 tick 按 `mpt` 流逝，不变 | `L.lifeMonths(st).m` 换成年：≥ 10 年写“寿元足”，否则“寿元 N 年”，≤ 5 年变红 |
| 负伤 | 月 | “负伤（下季末痊愈）”（§2.4） |
| 增益（聚灵丹 6 月等） | 月 | “还剩 N 季”，N = `ceil(left / 3)` |
| 访客等待 | 6 月 | “再等 2 季 / 本季就走” |
| 换阵、作物、拍卖、行情 | 月 | 一律 `ceil(月 / 3)` 季 |
| 闭关疲劳、屡败屡战等按次数算的 | 不变 | 不变 |

界面规则：**所有时长一律用“季”或“年”，不再出现“月”字**（修为的量仍可以写“+3 月修为”，那是量词）。`src/ui/core.js` 的 `UNIT` 改成 `'季'`，并加 `seasons(m) = Math.ceil(m / 3)`。验收：`grep -c "个月\|\${UNIT}" src/ui` 里凡是表示时长的都过 `seasons()`。

## 2. 一季怎么过

### 2.1 一季的流程

```
季初 ──→ 行动（3 点）──→ 点【下一季】──→ 季末结算 ──→（固定日子的大事）──→ 下一季季初
  │          │                              │                │
  │          └ 每个行动：做 → 结算卡 → 它的戏（当场）→ 回主界面
  │                                          └ 推 3 个 tick，一张季末卡
  └ 至多：一张解锁卡、一场闲戏、一位访客到门口（§4.4）
```

- **季初**：日期翻到新一季，行动点回满 3。按 §4.4 的顺序出季初的东西。
- **行动**：玩家随便排顺序。每个行动结算完，走一遍结算链（§4.2）。
- **【下一季】**：行动点没用完时，剩下的点**自动打坐**（每点 +1 月修为，按钮上直接写“剩 2 点 → 打坐 +86”，不弹确认框）。所以行动点一定花得完，不存在“浪费”。
- **季末结算**：`L.seasonEnd(st)`，见 §2.5。
- **固定日子的大事**：约战、论道、会武、来犯、新秀逼战。只在季末结算之后发生（§2.6）。

### 2.2 行动点价目表

每季 3 点。`L.AP = { per: 3, … }`（§3.6）。

| 行动 | 点 | 说明 |
|---|---|---|
| **历练**（任何地图、任何深度、任何行事；护送任务、人物委托的那一趟也是它） | **2** | 当场打完整趟（§2.3） |
| 趁势深入（历练结算卡上的那个按钮） | +1 | 手里还有点才出现 |
| 扫荡（已拿过甲、战力 ≥ 推荐 × 1.8 的格子） | 1 | 不播战斗，直接出结算。取代“连续历练” |
| 讨伐首领 | 1 | 一场回合战 |
| **闭关** | **2** | 当场得修为（§3.2） |
| 老祖特训（第一世只一次） | 2 | 约战前 3 季内可用 |
| 打坐 | 1 | +1 月修为。剩余的点自动做这个 |
| 秘境（要秘境令） | 2 | 进去以后和现在一样，一层一层选门 |
| **下战帖**（挑战主线点名的人物，§5） | 1 | 一场对决 |
| **拜山门**（投帖入宗，§5） | 1 | 出三宗的选择 |
| 宗门差事：指点师弟、讲法、传授功法给徒弟 | 1 | 原来占 2～4 个月的差事 |
| 问剑、阵前、圣子之战等主线的最后一仗（§5） | 1 | |

**不花点的**（一季里做多少次都行，只受资源和各自原有的次数限制）：

| 类 | 内容 |
|---|---|
| 身上的 | 换法宝、功法、灵宠、同伴；强化、淬灵、洗练、熔炼、打造；喂灵宠、派岗位 |
| 洞府的 | 建造、升级、换阵、种田、改种、炼丹（含自动续炼）、服丹 |
| 江湖的 | 坊市买卖、拍卖出价、宗门任务的接与交、宝库兑换、职司、晋升、给长老和人物送礼 |
| 人的 | 接见访客、看纸鹤、事件抉择 |
| 自己的 | **突破、渡劫**（修为圆满了随时点，不花点） |
| 固定日子的 | 三年之约、天骄论道、九宗会武、天剑来犯、新秀逼战（到日子就发生） |

为什么家务不花点：开罗的做法是“花钱的事随时做，花时间的事才占回合”。炼丹、种田、建造已经有灵石、灵草、地块、丹毒这些自己的限制，再叠一层行动点，玩家每季要做一道“炼丹还是历练”的算术题，那是加复杂度。

**一季的典型排法**（玩家实际只需要在这四种里选）：

| 排法 | 点 | 什么时候选 |
|---|---|---|
| 历练 + 一件小事（首领 / 下战帖 / 差事 / 打坐） | 2 + 1 | 默认 |
| 历练 + 趁势深入 | 2 + 1 | 这一趟打得顺 |
| 闭关 + 打坐 | 2 + 1 | 快圆满了、负伤了、冬季 |
| 三件小事（扫荡 ×2 + 首领，或打坐 ×3） | 1 × 3 | 缺某样材料、养伤 |

### 2.3 历练：花 2 点，当场打完

| 概念 | 现在 | 改成 |
|---|---|---|
| 时长 | 4～6 个月，一月一个节点 | 不占时间。节点数不变（3～5 个 + 归途），一口气走完 |
| “在外” | 历练 / 闭关期间是一个状态，什么都不弹 | **取消**。`st.exp` 只在这一趟的画面演出期间存在（存档里留着是为了中途退出能接着打） |
| 战斗 | 每个节点一场回合战 | 不变：走路 1.5 秒 → 战斗（每轮 1 秒）→ 下一个节点 |
| 结算 | 归来结算卡 + 归途翻牌 | 不变。最后一个节点打完立刻出结算卡和翻牌 |
| 途中遭遇 | 走到一半 60% 概率出一件事 | 不变：中间那个节点之后当场出（这是这一趟自己的事，不算打断） |
| 撤回 | 途中可撤，收获减半 | 战斗里的【撤】照旧（收获按现有规则）；节点之间不再有单独的“撤回”按钮 |
| 深度、地图、行事 | 地点 × 深度 × 行事 | 不变，都是 2 点。深的地方难、给得多，这个取舍现在就有，不需要再用点数区分 |
| 连续历练 ×3 | 金丹后可连去三趟 | **删除**，换成“扫荡”（1 点，不播战斗）。解锁表里的 `chainExp` 改名“扫荡”，门槛不变 |
| 负伤 | 丁等 / 倒下：负伤 3 月 | 负伤到下季末（§2.4） |
| 时长缩短类效果（御风诀、风行水上、轻灵词条、传送阵 3 级） | 历练时长 −1 月 | 改成**脚力**：每趟历练攒 0.25（每个来源 0.25，合计上限 0.75），攒满 1 返还 1 点行动点。结算卡上写“御风：返还 1 点” |
| 传送阵 9 级“秘境不耗月” | — | 改成“秘境只花 1 点” |
| 出发拦截（“来不及了：还有 N 月”） | 行程比离大节点的月数长就不让去 | **删除**。历练不占时间，不会撞上任何东西 |
| 节点前强制归来、收获折算 | 约战前 1 月提前叫回 | **删除** |
| 分身术（闭关时分身去外围一趟） | 不变 | 不变，随闭关结算 |

一趟历练的真实耗时：选格子约 10 秒 + 3～5 场战斗约 20～35 秒 + 结算与翻牌约 15 秒 ≈ **50～60 秒**。扫荡约 6 秒。

实现要点（给线 A）：

- `L.startExp` 之后不再等 tick。`L.tripStep(st, res)` 推一个节点（就是现在的 `L.expNodeDone`）；节点走完调 `L.tripEnd(st)` = `L.resolveExp(st)` + 扣点 + 记脚力。`e.left / e.total` 只当节点计数用。
- `L.expLen(k, st)` 只用来定节点数，不再套 `artExpLen / gearExpLen`（这两个函数改成返回“脚力来源数”）。
- `tick.js` 里 `if (st.exp) { … }` 整段删除；`L.seasonEnd` 开头断言 `!st.exp && !st.retreat`（有就先结掉）。
- 扫荡：`L.sweep(st, k, d, a)` = `startExp(…, { quick: true })` → `L.expRunRest` → `L.tripEnd`，不出途中遭遇。
- 界面的 `btDrive` 里 `btMonth()` 不再调 `L.flow(1)` 和 `onTick()`，只推节点。

### 2.4 负伤

现在的负伤是 3 个月，战力和修炼减半。一回合 3 个月，负伤就等于没罚。

**定案：负伤 = 带伤到下季末。** 实现上把负伤月数设成 4（本季末 −3 剩 1，下季末清零）：

| 来源 | 现值（月） | 新值（月） | 界面 |
|---|---|---|---|
| 历练丁等 / 倒下、突破失败、对决输（下战帖） | 3 | 4 | 负伤（下季末痊愈） |
| 首领战败（`expedition.js` 那处 4） | 4 | 7 | 负伤（两季） |
| 以伤换命（道心·狂）等小伤 | 1 | 1 | 负伤（本季末痊愈） |
| 灵泉“少养 N 月”、疗伤丹、破境丹疗伤 | 不变 | 不变 | — |

负伤时照样能行动（战力、修炼 ×0.5 的规则不变）。玩家自己会选“这一季闭关 + 打坐”。

### 2.5 季末结算

`L.seasonEnd(st)` 做的事，按顺序：

1. 剩余行动点自动打坐。
2. 连跑 3 次 `L.tick(st)`（每次先 `L.flow(st, 1)`）：自然修炼 3 个月、灵石收入 3 个月、寿元、增益倒计时、作物、丹炉续炼、灵宠、行情、宗门俸禄、宿敌、徒弟……全是现成的每月逻辑。
3. 把三次的 `out` 合并成一个 `S`：数值类相加（修为、灵石、收成、俸禄）；一次性的事（访客来了、大势起了、拍卖开槌、新秀出世）各只留第一次；`pact / tourney / meet / war / rookie / death` 记进 `S.big`。
4. 季数 +1，行动点回满，脚力不清。
5. 返回 `S`，界面出**季末卡**。

季末卡（一张，≤ 60 字，一个按钮）：

```
第 2 年 · 夏  结束
修为 +258（自然 +172 · 打坐 +86）     ← 修为条动一下
灵石 +340   灵田 收灵草 12
[这一季：历练 1 趟 · 乙 ｜ 首领 ✓]
下一季：入秋 · 采药 +20%                ← 有预告就写一行：三年之约 还有 2 季
                        【入秋 ▸】
```

- 冬季的季末卡换成**年报**（现有 `L.yearReport`，版式不变）。
- 季末卡是这一季唯一的例行弹窗。访客、大势、换季都**不再单独出横幅**，并进这张卡的最后一行。
- 寿尽在季末判；判到就走现有的寿尽流程。

### 2.6 固定日子的大事

| 大事 | 日子 | 发生的时点 |
|---|---|---|
| 三年之约 | 第 36 月 | 第 12 季的季末结算之后 |
| 天骄论道 | 每 12 月 | 每年冬季的年报之后 |
| 九宗会武 | 第 18 + 24k 月 | 隔年夏季的季末卡之后 |
| 天剑来犯 | `st.flags.war`（取 3 的倍数） | 那一季的季末卡之后 |
| 新秀逼战 | 论道之后追到身后 | 跟在论道后面 |

## 3. 修炼与成长数值

### 3.1 修为从哪来

| 来源 | 量 | 公式 | 备注 |
|---|---|---|---|
| 自然修炼 | 3 月 / 季 | 季末 3 × `L.gain(st)`（现有 `L.flow`） | 什么都不做也有。境界需求、倍率表全不动 |
| 打坐（1 点） | 1 月 | `L.gainCalm(st) × L.sitMult(st)` | `sitMult` = 原 `L.tunaStep`（引气诀让打坐多得） |
| 闭关（2 点） | 约 4～5 月 | `L.gainCalm(st) × 4 × (L.retMult(st) − 1)`，顿悟另得 2 月 | 见 §3.2 |
| 斩妖感悟 | 0.15～2 月 / 趟 | 现有 `xpTicks = 评价倍率` | 不变 |
| 老祖特训（2 点，一次） | 8 月 | `gainCalm × 4 × (3 − 1)` | |
| 丹药、事件、论道奖励 | 不变 | 不变 | |

**吐纳删除。** 吐纳环（每 6 个月蓄满点一下得 1 月修为）在没有“打坐态”之后没有意义，它的位置由“打坐（1 点）”接替。解锁表的 `tuna` 项删除；点主角不再有吐纳，改成打开【变强】页。`st.tuna` 迁移时折成修为（§7）。

### 3.2 闭关

- 花 2 点，灵石花费不变（`L.retCost`，第一次免费）。
- 当场得修为 `gainCalm × L.AP.retTicks(4) × (retMult − 1)`。`retMult` 的全部构成不变：基础 2、静室、烈阳诀、冬季 +0.2、名师讲道、闭关疲劳（两趟历练之间连着闭关每次 −0.5，最低 1.25）。
- 顿悟（30% / 道宗 45%）再得 2 月修为，不变。第一次闭关必顿悟、出关引来第一位访客，不变（访客在本季季末到）。
- 为什么是 `(m − 1) × 4`：现在闭关 4 个月得 `4m` 月修为，其中 4 个月是本来就有的自然修炼。新制里自然修炼在季末单独给，所以闭关只给“多出来的那一截”，量和现在完全一样。
- 道侣双修、讲道、指点师弟：原来走 `startRetreat / startBusy` 的，都改成当场结算，点数按 §2.2。

**一点行动点值多少修为**：打坐 1 月 / 点；闭关 2～2.5 月 / 点（要灵石、有疲劳）；历练约 0.5 月 / 点但给法宝和灵石。这就是每季的那道选择题，和现在“闭关还是历练”是同一道。

### 3.4 产出折算

**和现在比，变的只有“大事的密度”。** 现在一趟历练占 4～6 个月，一季（3 个月）折 0.5～0.75 趟；新制一季 1 趟，约 1.6 倍。修为这边，现在 guided 每 14 个月（两趟历练 + 一次闭关）得约 19 月修为，即每月 1.36；新制每 3 季（两趟历练 + 一次闭关 + 3 次打坐）得 9 + 3 + 4 = 16 月修为，即每月 1.78，快约三成。

所以按月计的东西**一律不动**，只压历练的材料产出：

| 产出 | 怎么折 | 常量 |
|---|---|---|
| 自然修炼、被动灵石、俸禄、灵田、灵宠觅食、徒弟、行情、增益时长 | 不动（每季自动结 3 个月） | — |
| 历练的灵石、灵草、灵矿、贡献 | × **0.65** | `L.AP.expRew = 0.65`，乘在 `expCalc` 的 `stones / herbs / ore / contrib` 上 |
| 历练掉破境丹、天材地宝、灵宠的概率 | × 0.65 | 同上（乘在 `L.EXP_PILL`、`treasure`、`pet` 那三处概率上） |
| **归途翻牌（法宝、功法、灵核）** | **不动** | `L.AP.lootRew = 1`。每趟翻几张、出什么，和现在一样——刷宝的手感不能稀释 |

| 首领、秘境、论道、会武的奖励 | 不动（次数本来就受首领数、秘境令、届期限制） | — |
| 扫荡 | 和正常历练同一套结算（已含 × 0.65），不出途中遭遇 | — |

法宝因为翻牌不折、趟数多了六成，会比现在出得快。它被地图卡着（地图要境界才开），所以最多快半阶。校准时若 guided 在第三章末的兵器阶比现在高出 1 阶以上，把 `L.AP.lootRew` 降到 0.8（每趟翻牌数按概率取整）。

## 4. 剧情零延迟（重点）

### 4.1 一句话规则

> **一件事结算完，它引出的所有阻塞内容当场连着出完，然后才回到主界面。期间不过季、不扣点、不插无关的东西。**

“延迟”的定义（测试也用这个，§8.3）：从触发条件成立到这场戏开播之间，玩家做了几个行动、过了几季。**关键剧情的延迟必须是 0 个行动、0 季。**

### 4.2 结算链

所有结算都走同一个入口。界面 `settle()`（新，`src/ui/settle.js`）在每个行动结束、每次季末结算之后调用，循环到没东西为止：

```
settle():
  loop:
    x = L.nextBlock(st)        // 逻辑层按下面的优先级给出下一张要出的东西；没有就返回 null
    if (!x) break
    await show(x)              // 结算卡 / 对话场景 / 过场 / 对决 / 章末卡 / 解锁卡
  回主界面，刷新目标卡
```

`L.nextBlock(st)` 的优先级（一条链里从上到下，出完一类再出下一类）：

| 序 | 什么 | 例 |
|---|---|---|
| 1 | 这个行动自己的结算卡 | 历练结算与翻牌、对决结果、突破结果、季末卡 / 年报 |
| 2 | 这件事直接触发的系统剧情 | `beat:<id>`、`boss:5`、`trib:1`、`demon:N`、`sect`（入宗第一天）、`srank:N`、`rank:12`、`daolv` |
| 3 | 本章节拍里已经到点的：`climax` → `end` | 赵乾落败 → 那一脚的来历 → 没渡完的劫 |
| 4 | 章末结算卡 | “第三章 旧怨 · 完” |
| 5 | 下一章的 `open`（含因境界先到而记着的 `realm:N`，§4.5） | “第四章 立名”→ 残缺的剑诀 |
| 6 | 这件事“已经发生”所以必须立刻开的解锁卡（`force` 类） | 拿到第一只灵宠 → 灵宠解锁卡 |
| 7 | 固定日子的大事（只在季末那条链里） | 年报 → 论道 → 新秀逼战 |
| 8 | 季初的东西（只在季末那条链的最后，§4.4） | 一张排队的解锁卡、一场闲戏 |

规则：

- **链里不出无关的东西。** 访客到、换季、大势、拍卖开槌、宿敌消息在链进行中一律不弹，写进季末卡或纸鹤。
- **链不会断在半路。** 链里的每一张都是阻塞层，关掉一张立刻出下一张；中间不显示主界面、不让点底栏。
- **存档点**：每出完一张存一次。读档时先调 `settle()`，没出完的接着出（靠的是 `st.storyQ` 和节拍状态都在存档里）。
- **跳过**：对话场景仍可一键跳过（给梗概），抉择跳不掉。跳过也算“播了”。

### 4.3 节拍放在哪个时点

| 节拍 | 现在 | 改成 |
|---|---|---|
| `open` 开章 | 进入本章后第一次在洞府空下来；`GAP 2` 月 | **上一章章末卡关掉的那一刻**，同一条链。第一章的开章在建档后当场播（现状） |
| `mid1`～`mid3` 中段 | 距上一场 ≥ 6 月，进度过 20% / 45% / 70%（或入章 18 / 36 / 54 月） | **季初**。进度过 20% / 45% / 70%，或入章满 3 / 6 / 9 季。一个季初最多一场 |
| `pre` 高潮前 | 进度 ≥ 85%；`GAP 3` 月 | **最后一仗开打之前，当场。** 玩家点了【下战帖】【赴约】【迎战】之后、对决画面之前。固定日子的仗（约战、守山）：在“本季末”那一季的季初播 |
| `climax` 高潮 | 最后一仗打完以后的下一个空档 | **最后一仗的结果卡关掉的那一刻** |
| `end` 章末 | 主线完成后；`GAP 1` 月 | **`climax`（及其抉择）结算完的那一刻**，后面紧跟章末卡 |
| 章末结算卡 | `chapter` 事件触发，在外时等回洞府 | `end` 之后立刻 |

一章收尾的完整链（例：第三章，玩家点【下战帖 · 赵乾】）：

```
点【下战帖】→ pre（s3_zhao_eve，没播过才播）→ 对决 → 结果卡
  → beat:zhao 的系统戏 → climax（s3_zhao_fall，含抉择）→ end（s3_end）
  → 章末卡“第三章 · 完”→ 第四章 open（story_r3）→ [灵宠之类 force 的解锁卡] → 主界面
```

这条链很长（约 4～6 分钟），这是对的：它就是这一章的大结局。链里**不扣第二个行动点、不过季**。

**打输了**：结果卡 → 败北的那场戏（有就播）→ 主界面。这一仗过 `retry` 指定的时间可以再打（现有 `fx.retry`，月数向上取到季；没写的默认下一季），目标卡“下一步”写“再战：赵乾（下一季）”。

### 4.4 闲戏、访客、解锁卡怎么分到季里

**季初**（季末那条链的最后一段，按这个顺序，每类最多一件）：

| 序 | 什么 | 上限 | 说明 |
|---|---|---|---|
| 1 | 主线 `mid` 节拍 | 1 场 / 季 | 主线戏优先于人物戏 |
| 2 | 人物戏（`sb:mid` 的空位、奇遇链的剧情步、人物线） | 1 场 / 季，且这一季没有主线 `mid` 才出 | |
| 3 | 排队的系统解锁卡 | 1 张 / 季 | 按 `L.ONB` 顺序，§4.6 |
| 4 | 访客到了 | 1 位 / 季，**不阻塞** | 门口出“！”，纸鹤 +1，目标卡下面的传讯行说一句。点了才见，见访客不花点 |
| 5 | 大势、换季、拍卖开槌、新秀出世 | **不阻塞** | 已经写在上一张季末卡的最后一行；这里只是入口挂角标 |

- 季初的阻塞内容合计**最多 2 件**（一场戏 + 一张解锁卡）。排不上的留到下一季季初，不丢。
- 本季末有大事的那一季，季初只出 `pre`（如果有），别的都让路。
- **不拖延的保证**：主线 `mid` 最多晚 1 季（被上一季的 `mid` 挤了才会）；解锁卡最多排 `L.ONB` 里前面还有几张就晚几季，而一章要开的系统 ≤ 7 张、一章 ≥ 12 季，排得完。

**季末**（季末卡之前，最多一件）：洞府事件抉择（现有 `where: 'home'` 的随机事件），每季最多一件；这一季有过途中遭遇就不出。

**行动之中**：只有这个行动自己的东西（途中遭遇、秘境里的事件、战斗里的第一次提示）。

**老祖的话**：非阻塞的传讯行 / 气泡每季最多一条，季初出；阻塞讲解只剩头三步手把手（KAIRO §5.1 第 2 条）。

### 4.5 境界先到、章没到（`st.path.hold`）

这条机制保留——它管的是**顺序**（`realm:N` 的戏必须按章出），不是节流。改的是放出的时点：

- 现在：章到了以后“一个月放一个键，前一个结算完才放下一个”。
- 改成：章一变（章末卡关掉），`L.nextBlock` 在同一条链里把到期的键按章序**连着放完**。“前一个结算完才放下一个”由链的串行天然保证。
- 一条链里因补发而连播的主线戏最多 3 场（开章和带抉择的不计入上限）；超出的留到下一季季初，每季初 1 场。只有“一口气跨过两章”这种情况才会碰到上限。

### 4.6 解锁卡

| 类 | 例 | 什么时候出 |
|---|---|---|
| `force`（已经发生） | 突破、三年之约之后的天骄榜、入宗、拿到灵宠、遇见人物、拿到战技 | **当场**，那件事的结算链尾（§4.2 第 6 级） |
| 排队（原门槛满足、上一样已掌握） | 洞府、闭关、强化、坊市、灵田、丹炉、秘境…… | **季初**，每季最多一张 |

节流规则只剩两条：系统卡之间至少隔 1 季（`unlockGapMonths: 3`）；上一个系统没掌握（或没等满 `maxWait`）不开下一个。**真实时间那一半（`unlockGapSec`、`L.onbHold`、`lastCardSec`、`watchSec`）整个删除**——回合制下“6 分钟”没有意义，间隔由季数保证。

## 5. 主线可推进性

### 5.1 规则

> **任何时刻，目标卡“下一步”的【去】都指向一个现在就能做的行动；这个行动做成了，主线进度条一定动。**

- 主线里每一个“要打的人”“要进的门”都有一个**玩家主动发起的行动**，不依赖“他正好排到你前面”“有人正好来请你”。
- 行动暂时做不了时（差战力、差贡献、对方不应战），【去】指向**能补上这个差距的行动**，并写明差多少：“下战帖：赵乾（胜算 34% → 建议 60%）”照样能点；“贡献 1200 → 2000：去交任务”。
- 散修（`L.loneRoute`）和入宗两条路各有一张表，不存在“这条路上这一章没有可做的事”。

本节和另一条在修的“可达性修复线”重叠的部分（第三章散修无人邀请、点名的人打不到）：以本节为准，那条线的修补合进线 B。

### 5.2 新增的三个主线行动

**下战帖**（`L.challenge(st, id)`，1 点）

- 对象：当前章主线点名、还没打赢的人物（慕容——三年之约输了以后、赵乾、楚天阔、血无涯、云无极），以及主线要求的名次门槛前面那一位（“进前 60”时是你前方最近的、打得过的一位）。
- **主线点名的人永远应战**：不看他在榜上离你多远，不看 `L.rivalRefuses`（“你的小层不到他不上台”对主线目标不生效；他的战力仍按 `L.RIVAL_WALL` 卡位，所以打不打得过照旧由战力说话）。
- 结算与论道的一场相同（`L.duelWin`，同样的胜算公式、五行、法宝克制、玄霄重掷）。赢：`st.beaten[id]`、`L.markBeat`、恩怨、名次上升（最多升 `L.TOUR_STEP` = 15 名，且不越过没打赢的卡位宿敌）。输：负伤到下季末，这个人 **4 季内**不再接你的帖子（`st.rv2.cool[id] = st.tick + 12`）；每年的论道不受这个冷却影响。
- 每年的天骄论道照旧（不花点、三场）。下战帖是“不想等到年底”的路。

**拜山门**（`L.knock(st, id)`，1 点）

- 条件：三年之约已了结、没有宗门、不是“无宗”试炼。不看境界（现在要筑基才有人来请——这正是散修存档卡住的原因）。
- 效果：直接出该宗的入门抉择并 `L.joinSect`（血煞魔宗仍要 `L.sectJoinable`）。入宗当场接 `sect` 的戏（入宗第一天）。
- 第二章开章链的末尾仍会出一次“三张帖子”（抉择二）。在那里选了“哪家也不去”的，之后随时可以拜山门改主意；一直不拜的走散修表。

**主线的最后一仗**（`L.finalFight(st)`，1 点）

- 第四章圣子之战、第七章阵前、第八章问剑天剑宗：现在分别挂在晋升、`retry` 计时、节拍上，改成条件满足后目标卡出【去】，玩家点了才打。条件不满足时【去】指向差的那一项。
- 第六章守山、第一章约战是固定日子的，不用点。第九章天劫就是【渡劫】（不花点）。

### 6.3 主循环

```js
function nextSeason() {

  const S = L.seasonEnd(st);            // 逻辑层：打坐、3 个 tick、合并

  settle();                             // 季末卡 → 大事 → 季初（§4.2）
  saveLocal();
```

## 10. 接口（线 A 提供，线 B / C / D 调用；A1 冻结）

```js
// ---- 常量 ----
L.SEASON_LEN = 3
L.AP = { per, exp, deeper, sweep, boss, retreat, train, sit, realm, realmPortal, duel, join, errand, final,
         sitTicks, retTicks, expRew, lootRew, stride, strideCap }
L.AP_ON            // sim 对照：false = expRew 1、负伤 3 月

// ---- 存档 ----
st.ap = { left,        // 本季还剩几点
          stride,      // 脚力（0～1）
          debt,        // 下一季要扣的点（事件占时）
          seq,         // 行动序号：每个行动、每次季末 +1（剧情延迟用）
          pend: [],    // 迁移时到期、还没出的大事
          log: {} }    // { 季序号: { spent, acts: [id…] } }，只留最近 8 季
L.migrateAp(st)      // 幂等

// ---- 日历 ----
L.seasonNo(st)       // floor(tick / 3)，0 起
L.seasonNow(st)      // 本回合是哪一季：L.seasonOf(st.tick + 1)（界面、换季加成的预告都用它，不要直接用 L.season(st)）
L.seasonsLeft(m)     // ceil(m / 3)
L.dateText(st)       // '第 2 年 · 夏'

// ---- 行动点 ----
L.apLeft(st)
L.apCost(st, id, args)          // 这个行动花几点（含传送阵等修正）
L.apWhy(st, id, args)           // '' = 能做；否则一句原因（'点不够（下一季）'、原有的各种 why）
L.act(st, id, args)             // 统一入口：检查 → 执行 → 扣点 → seq++ → 返回这个行动的结果对象（null = 没做成）
L.regAct(id, { ap, why, run })  // 登记一个行动（线 B 的下战帖、拜山门、最后一仗用它登记）
// 已登记的 id：'exp'（args: k, d, a, opt）、'sweep'、'deeper'、'boss'（k）、'retreat'、'train'、'sit'、'realm'、
//             'errand'（args: 任务序号 / 徒弟与功法）、'duel'（id）、'join'（宗门 id）、'final'

// ---- 历练（当场） ----
L.startExp(st, k, d, a, opt)    // 不变；之后界面逐节点打
L.tripStep(st, res)             // 推一个节点（原 L.expNodeDone）；返回 { done: 是否走完, enc: 途中遭遇事件或 null }
L.tripEnd(st)                   // 结算（原 L.resolveExp）+ 扣点 + 脚力；返回结算对象（多了 refund: 0 | 1）
L.sweep(st, k, d, a)            // 扫荡：返回结算对象

// ---- 修炼 ----
L.sit(st)                       // 打坐 1 点 → 得到的修为
L.sitGain(st, n)                // n 点打坐能得多少（按钮上的预览）
L.retreatNow(st)                // 闭关 → { got, epi, fenshen, contrib, visitor }
L.retInfo(st)                   // 不变（len 仅作文案），多 gotNow：这次能得多少

// ---- 回合 ----
L.seasonEnd(st)                 // → S = { season, tick, sat: 自动打坐的点数, xp: { flow, sit }, stones, crops, pay,
                                //         notes: [非阻塞的一行字…], big: [{ k: 'pact'|'tour'|'meet'|'war'|'rookie'|'death' }],
                                //         visitor, year: 是否年末, next: { cal 加成, bigSoon: { n, seasons } } }
L.seasonReport(st, S)           // 季末卡的显示数据

// ---- 结算链（缺省实现在 ap.js，线 B 在 storyline.js 包成完整版） ----
L.nextBlock(st)                 // → null | { kind: 'result'|'story'|'chapter'|'unlock'|'big'|'year'|'season', id, data, lv: 1～8 }
L.blockDone(st, x)              // 界面出完一张后回调（记 lag、弹出队列）
L.chainOpen(st, why)            // 一条链开始（why: 'act' | 'season' | 'load'）；重置链内计数
```

界面 → 逻辑的调用约定：**界面不直接改 `st.ap`，不直接调 `L.tick`。** 花点的事一律 `L.act`；过季一律 `L.seasonEnd`；出什么一律问 `L.nextBlock`。
