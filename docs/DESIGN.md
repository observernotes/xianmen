## 0. 结论先行

### 0.1 现在的游戏为什么“糙”

1. **节奏塌了。** 一个周天 5 秒，引导型玩家 22 个周天筑基、26～28 金丹、34～38 元婴（`tools/sim.js` 8 个种子）。筑基、三年之约、灵根觉醒、三宗争徒、入宗第一天全挤在第 24～26 周天；入宗后 18 个周天就当上圣子。修仙最大的爽点“境界”一个接一个闪过去，来不及看。反过来，天骄榜第一在第 120～168 周天就拿到，之后到飞升（第 187～279 周天）没有可追的东西。
2. **弹窗跑步机。** 历练一趟 2 周天（10 秒），回来必弹结算窗，一半概率再弹奇遇窗，然后要点 3 下重新出发。实测 ×1 速度前 5 分钟弹了 33 个窗；×4 速度 413 秒里 141 个窗（60 个周天，平均每周天 2.35 个）。玩家大部分时间在关窗，没有“看着数字涨”的空当，好看的场景也没人看。
3. **没有取舍。** 洞府四项永远是“哪个便宜点哪个”；每个境界只有一张地图打得动（推荐战力一跳 11～33 倍，而玩家每小层才 ×1.5）；历练期间照常修炼，所以永远不该待在家；寿元从不构成压力（飞升时 7000/38580 岁）；破境丹攒到 138 枚、灵石攒到 2700 万花不掉；筑基一觉醒就是满级的“混沌圣体”，洗髓丹第一世直接显示“灵根已至巅峰”。
4. **引导只管前 2 分钟。** 12 步脚本做得不错，但能被带偏（结算窗的金色主按钮是“再去一次”，点了引导就卡在原地；第一次历练保底成功对任何地图都生效，直接选落日古墓白拿 1163 灵石和“越级挑战成功”）。脚本结束后只剩一条线性目标和一次性提示，卡住时没人告诉你为什么。
5. **界面像表格。** 全屏 12px 字，主界面 7 个同色暗框上下堆叠；面板是文字卡片列表，价格按钮 56×28、关闭按钮约 20px、图标按钮 32×24，都小于 44px；场景画布 200px 宽被拉到 380px（1.9 倍，非整数），像素粗细不均；对决只是两张头像抖 1 秒；成就横幅一次叠三条盖住主角。
6. **人物一张脸。** 15 个有名有姓的角色共用同一个 Q 版脸模板，只换发色和袍色，葛老是白头发的娃娃脸，老祖是一个 20 像素的蓝色水滴。人物只在随机弹窗里出现，羁绊就是一根涨到 60 的进度条。
7. **转世没有理由。** 第一世几乎不会死；飞升后的转世只多一个倍率和一张天赋卡，内容完全一样。关掉游戏没有离线收益，也没有“明天再来”的钩子。

场景美术（洞府、11 张历练地图、昼夜四季、渡劫动画）和奇遇文案是现有最强的部分，全部保留并围绕它们重做。

### 0.2 关键设计决定

| # | 决定 | 一句话理由 |
|---|---|---|
| D1 | 第一世拉长到约 600～650 周天，每个大境界 35～90 周天 | 让每个境界有自己的地图、对手、宗门身份和故事，而不是 20 秒 |
| D2 | 历练改成“项目”：选地点 × 深度 × 行事，4～6 周天，途中看收获累积，回来盖印评价（天甲乙丙丁） | 学游戏发展国的“开工—看数字冒—评分揭晓”循环，一轮 40～90 秒 |
| D3 | 新增【闭关】：花灵石，4 周天修炼 ×2；历练期间修炼 ×0.5 | “出去拿资源”和“在家涨修为”成为真正的二选一，灵石多了一个去处 |
| D4 | 不请自来的弹窗只留给决策和大事；奇遇改成洞府门口的访客气泡，其余全部用场景内飘字和右上角传讯条 | 前 36 周天阻塞弹窗从 33+ 降到 ≤14，弹窗内时间占比 ≤40% |
| D5 | 觉醒分四次（筑基、元婴、炼虚、大乘），洗髓丹可以提前一档 | 灵根一路都有成长，洗髓丹有用 |
| D6 | 老祖常驻：左下角头像随时可问“现在该干嘛”，回答永远带数字；每章 3 个并行小任务代替单线目标 | 直接回应“根本不知道怎么玩” |
| D7 | 天骄榜对手按“设计好的超越时间”成长，榜首要到大乘、渡劫才打得过 | 一辈子都有人可追 |
| D8 | 人物重画成 48×48 独立半身像（三种表情），好感改成五颗心，三心知己、四心同行（历练带一位同伴） | 人物有脸、有用、有戏 |
| D9 | 一世结束结算“道果”，在轮回殿买永久加成；新增出身和天道试炼；图鉴跨世保留 | 每一世不一样，转世有明确动力 |
| D10 | 砍掉：丹炉自动产破境丹、顶栏破境丹/排名常驻显示、主界面消息卷、一次性 tip 条、赤裸的随机事件 `randomEvent`（并入事件库） | 少而清楚 |

## 2. 设计支柱与核心循环

### 2.1 五条支柱（做任何取舍时按这个顺序判断）

1. **永远知道下一步。** 任何时刻屏幕上有且只有一个发光的“推荐操作”，点它不超过两下就能完成；不知道干嘛就点老祖。
2. **数字一直在涨，而且看得见为什么。** 每个操作前显示“现在 → 之后”，操作后数字滚动到新值；每个数值点开都能看到由什么组成。
3. **少弹窗，多飘字。** 世界在跑的时候不打断玩家；只有“要你做决定”和“值得停下来看”的事才暂停时间。
4. **每个选择都有代价。** 灵石、周天、寿元三样都不够用：去历练还是闭关，升聚灵阵还是买破境丹，稳拿乙等还是冒险闯禁地。
5. **人物有脸，一世一个故事。** 对手会成长、会记仇；同伴能带出门；这一世拜了谁、娶了谁、输给过谁，下一世还记得。

### 2.2 三层循环

**分钟级（40～90 秒一轮）——“出门一趟”**

```
洞府空闲 ──选：历练（地点×深度×行事）或 闭关──▶ 进行中 4～6 周天
   ▲                                                │ 场景里自动打怪/打坐，收获计数一格一格涨
   │                                                │ 中途最多一次遭遇抉择（历练）
   │                                                ▼
花灵石（升级/坊市/炼丹）◀── 结算：盖印评价 + 掉落揭晓 + 战力/修为前后对比
```

- 一轮里玩家做 2～3 个决定（去哪、怎么去、回来买什么），看 1 次揭晓。
- 每 2～3 轮升一小层（修为条满，自动升层，战力 ×1.5，场景里炸一圈灵光）。
- 结算是唯一必弹的窗；其余反馈都在场景里。

**一次游玩（10～20 分钟）——“一届论道”**

- 每 12 周天一届天骄论道，是固定的“期末考”：考前老祖给出本届锦囊（最划算的 3 件事及各自能涨多少胜算），考完榜单滚动、宿敌出场。
- 每个大境界是一章：开头一段主线和一次觉醒/新地图/新身份，结尾一次突破（金丹起渡劫）。一章 35～90 周天，正好是一次游玩。
- 章末结算卡（学游戏发展国的年终总结）：本章用了多少周天、历练几趟、最高评价、榜上升了几名、结识了谁；点“下一章”继续。

**一世与多世（60～90 分钟一世）——“道果”**

- 一世以飞升或坐化结束，结算道果（分数），在轮回殿换永久加成。
- 下一世换出身、换宗门、换道侣、加天道试炼；图鉴、成就、称号、前缘跨世保留。
- 第一世的目标是飞升；第二世起的目标是“更高的道果”和“没见过的结局”。

## 3. 数值模型

写法约定：`r` 大境界 0～8，`s` 小层 0～3，`i = 4r + s`（0～35）。周天 = 一个 tick，×1 速度下 5 秒。下面的常数是**起始值**：我用一个独立原型（`model.js`，参数全文见附录 A）跑过 100 个种子，结果列在 §3.12；阶段一实施时把它们搬进 `logic.js`，再用新的 `tools/sim.js` 校到 §3.12 的目标区间。公式结构不要改，常数可以调。

### 3.1 时间与速度

> **3.0 起由 `docs/AP_PLAN.md` 取代**：时间不再按真实秒数流动，没有速度档与暂停键。底层 `st.tick` 仍按月（1 tick = 1 月），一回合 = 一季 = 3 个 tick，每季 3 点行动点，点【下一季】才推进；界面上的时长一律写“季 / 年”（`seasons(m) = ceil(m / 3)`）。下面的 `TICK_MS`、速度档只作历史对照；`MPT`（每月流逝的年数）照旧。

- `TICK_MS = 5000`。速度档 ×1 / ×2 / ×4，**暂停单独一个按钮**（不再混在循环里）。
- 弹窗打开、老祖阻塞讲话、过场动画时时间停；非阻塞气泡、传讯条不停。
- 界面上所有倒计时、时长一律用“周天”。“三年之约”只作为事件名出现，旁边永远跟着“还剩 N 周天”。顶栏不再显示“第 N 年”，年份只在【人物】页和章末结算卡里出现。
- 每周天流逝的年数 `MPT = [1/12, 1.6, 2, 3, 5.5, 11, 20, 42, 80]`（炼气期 12 周天一年，所以三年之约 = 第 36 周天）。

### 3.2 修为

```
基础修炼   g0(i) = 10 × 1.30^i                      // 倍率为 1 时每周天的修为
基准时长   T0(i) = TR[r] × SW[s]
           TR = [50, 150, 400, 820, 1500, 2500, 4200, 6800, 10000]   // 该境界在倍率 1 下的总周天
           SW = [0.19, 0.23, 0.27, 0.31]
升层所需   need(i) = 取整到两位有效数字( g0(i) × T0(i) )
每周天修为 gain = g0(i) × 灵根 × 功法 × 聚灵阵 × 宗门 × 羁绊 × 丹药 × 状态 × 轮回

### 3.4 战力与对决

```
战力 P = 10 × 1.5^i × 1.8^r × 灵根战力 × 法宝 × 灵宠 × 宗门 × 羁绊 × 增益 × 轮回 ×（负伤 0.6）
法宝   [1, 1.3, 1.7, 2.3, 3.1, 4.2, 5.7, 8]          // 不变
灵宠   [1, 1.2, 1.45, 1.75, 2.1, 2.5, 3.0]           // 不变
对决胜率 = clamp(0.5 + 0.55 × log2(我 / 敌), 0.03, 0.97)   // 不变
```

每小层 ×1.5、每大境界再 ×1.8（合计约 ×9.1）保留——这是“突破一下战力翻几倍”的爽点来源。

因为胜率曲线很陡，界面在显示胜算的任何地方同时显示**“稳赢线”**：`敌 × 1.8`（97%）和**“五五线”**：`敌 × 1.0`，并把差距翻译成一句话，例如“再升一小层就到五五开”“换一把法器就稳了”。计算方法：枚举【升一小层 / 法宝 +1 阶 / 灵宠 +1 阶 / 突破大境界】四种情况各自的新胜率，取玩家当前最容易做到的一项（见 §4.4 锦囊）。

战力等于推荐值、相性 ○ 时：分数 58～82，约七成乙、三成丙，不会丁；两倍推荐战力约八成甲（其中少数是天）；一半推荐战力时约六成丁。出发确认页显示“预计评价 乙～甲”和“负伤风险 N%”（把上面的分布算出来，不显示公式）。

结算时把分数拆成四项小分依次亮起（只是展示拆分，总和等于分数）：**斩获** = 战力比那一项；**机缘** = 随机项；**身法** = 相性项；**胆魄** = 深度、同伴与称号那几项加成。

**行事**（第二趟历练解锁采药，第四趟解锁寻宝）：

相性表（每张图恰好一个 ◎、一个 ○、一个 △，顺序为 斩妖/寻宝/采药）：后山野林 ○△◎；黑风岭 ◎○△；落日古墓 △◎○；万妖山脉 ◎△○；血煞秘境 ○◎△；上古剑冢 △◎○；九幽魔渊 ◎○△；东海龙宫 ○△◎；天外星墟 △◎○；太古仙府 ○◎△；混沌裂隙 ◎△○。未试过的组合在选择页显示“？”，试过后永久显示符号（存 `st.meta.aff`，跨世保留）。

**掉落**（`m` = 奖励倍率）：

```
灵石   = rew(k, d) × m × 行事 × (0.9～1.1) ×（锦鲤 1.5）×（夜璃同行 1.2）
灵草   = (2 + k) × (1 + 0.5d) × 行事 × m
破境丹 = 40% 概率 1 枚
法宝   = 0.30 × m × 行事 概率；阶 = 1 + floor((3k + d) × 0.21)，15% 概率再 +1
功法   = 0.25 × m × 行事 概率；阶 = 1 + floor((3k + d) × 0.18)
灵宠   = 筑基后 0.06 × 行事 概率；阶 = 1 + floor(k × 0.5)
天材地宝 = (0.03 + 0.01k) × 行事 概率
宗门贡献 = 入宗后 10 × 2.3^k × m
```

同阶或更低的法宝功法自动折成灵石（寻宝价的 30%），不进背包——本作不做背包。

**途中遭遇**：第 `ceil(len / 2)` 周天有 60% 概率触发一个 `where: 'exp'` 的事件（阻塞，带选项）。成功的选项给事件原有奖励并使本趟分数 +5，失败 −5。引导期间（前两趟）不触发。

**首领**：某张图禁地评价乙以上一次后，首领出现在该图的选择页顶部。首领战力 `rec(k, 2) × 1.6`，用对决公式，奖励沿用现有 `L.fightBoss`（天材地宝、专属法宝、称号）。

**保底**：第一世第一趟固定为后山野林外围、斩妖、评价甲、掉一把凡器（现有“第一次必成功”对所有地图生效的漏洞同时修掉：引导完成前其它格子不可选）。

**自动连续历练**（金丹解锁）：出发页多一个开关“连续 ×3”，回来不弹结算，三趟合并成一张结算卡；任何一趟丁等、遭遇事件或修为圆满时中断。用来减少后期点击，不改变收益。

### 3.6 闭关

```
解锁     炼气中期（第一次免费，引导用）
时长     4 周天，可提前出关（不退灵石）
花费     ret(i) = 25 × 1.27^i 灵石        // 炼气初 25，筑基初 65，金丹初 169，元婴初 440，化神初 1145，渡劫初 5.2 万
效果     修炼 ×(2 + 0.05 × 洞府等级)；期间访客事件顺延；出关时 30% 概率“顿悟”，再得 2 周天修为
限制     闭关与历练互斥；负伤时可闭关（负伤照常扣 ×0.5），负伤每周天自然恢复
```

闭关一轮净多得约 4 周天的修为，花掉约 1～2 周天的灵石收入；历练一轮净少 2～3 周天的修为，多得约 5～12 周天的灵石，外加掉落。这组数字就是“出去还是在家”的取舍，面板上直接写出来：“闭关：修为 +N（约提前 M 周天升层），灵石 −C”“历练：灵石约 +N，修为少 M 周天”。

**疗伤**：负伤时【洞府】顶部出现“服丹疗伤”按钮，花 1 枚破境丹立刻痊愈（给破境丹第二个用途，也解决失败后只能干等的问题）。

## 4. 引导

### 4.1 原则

1. **老祖有三种说话方式**，实现成三个明确的通道：
   - **讲解**（阻塞）：遮罩 + 高亮一个控件 + 气泡，时间暂停。只用于“第一次出现的功能”和“大事前的提醒”，每条一生只出现一次。
   - **气泡**（非阻塞）：左下角老祖头像上方冒一行字，4 秒后收起成头像上的“！”，点头像可重看。时间不停。用于提示、催促、解说。
   - **问答**：玩家主动点老祖头像，得到“现在最该做的一件事”，带数字和【前往】按钮。
2. 每句话不超过两行（412 宽下约 44 个字），**必须带至少一个具体数字**，说完立刻能动手。
3. 讲解期间只有被高亮的控件能点；玩家点了别处，气泡抖一下并重复一遍，不前进也不卡死。每条讲解右下角有“跳过引导”，跳过后所有讲解标记为已读，气泡和问答仍然工作。
4. 引导期间不该出现的东西直接不出现（而不是“出现了但别点”）：第一趟历练只有一格可选；第一张结算卡没有“再去一次”；前两趟没有途中遭遇；E09 之前没有访客。
5. 同一时间最多一条讲解；两条讲解之间至少隔 2 周天；气泡每 3 周天最多一条（大事提醒除外）。
6. 女主角时“小子”换成“丫头”，`{ex}` 是退婚者的名字，`{…}` 都是运行时算出来的数。

### 4.4 问答与锦囊

**点老祖头像**，按下面的顺序找到第一条成立的，给一句话加【前往】：

1. 修为圆满 → “点境界牌冲{境界}，成功率 {p}。”
2. 下一件大事 ≤ 6 周天且胜算 < 85% → 锦囊第一条。
3. 负伤 → “先疗伤：服丹，或歇 {n} 周天。”
4. 有访客在等 → “门口有人，去看看。”
5. 能晋升 / 有可领的任务奖励 → “去宗门领了。”

7. 买得起的升级里性价比最高的一项（聚灵阵按“每灵石提前的周天数”，灵田按回本周天）。
8. 离完成最近的一条札记任务。
9. 都不成立 → “照现在这样，{N} 个周天后升{下一层}，战力到 {x}。稳着呢。”外加一句闲话（从 12 句里随机，随主线进度解锁，见 §7.2）。

```

## 5. UI 与交互

### 5.1 通用规则

- **像素对齐**：所有像素图（场景画布、头像、图标、边框）按“整数个设备像素”放大。`n = round(dpr × 2)`，场景 CSS 宽 = `逻辑宽 × n / dpr`；逻辑宽固定 200，屏幕不足时居中裁到最少 180，多出的宽度留给两侧边距。头像、图标同理（16 逻辑像素的图标显示为 `16 × n / dpr`）。
- **字号三档**（都是 12 像素字模的整数倍设备像素，沿用 `setFontSize` 的算法，`k = round(dpr × 1.2)`）：小 `--fs = 12k/dpr`（说明、标签）；中 `--fs-m = 12(k+1)/dpr`，dpr < 1.5 时等于小（数值、按钮、人名）；大 `--fs-l = 24k/dpr`（标题、评价、境界名）。不得出现其它字号。
- **点击目标** ≥ 44×44 CSS 像素；列表整行可点；底部按钮高 48；关闭按钮 44×44 放右上角。
- **按钮层级**：金色 = 本屏唯一的主操作；纸色 = 次要；朱红 = 不可逆（重新开始、兵解）；灰 = 不可用，且按钮下方必须写原因（“还差 23 灵石”）。任何弹窗里高亮的都是“往前走”的那个。
- **颜色语义**：修为 = 玉绿 `#4ccb9f`；战力 = 珊瑚 `#ff9a8a`；灵石 = 青 `#7fe0f0`（图标与数字同色）；金 `#f4c542` 只用于“可操作/达成”；朱 `#c8323c` 用于危险和印章；品阶色：凡 `#b8b8b8`、法 `#62d26f`、灵 `#4aa8ff`、宝 `#c27dff`、灵宝 `#ffb23f`、仙 `#ff6b6b`、混沌 彩虹。
- **弹窗预算**：不请自来的阻塞弹窗只有：结算卡、途中遭遇、主线、大事（约战/论道/会武/突破/争徒/章末）、老祖讲解。其余一律气泡、飘字、传讯条。关闭弹窗后 400ms 内不弹下一个，并且队列里的下一个先以“传讯条 + 可点”的形式出现 1 秒。
- **数字变化**：任何 HUD 数值变化都用 300ms 滚动；增加时闪绿，减少时闪红。

## 附录 B：审计中确认的缺陷（阶段一、三顺手修）

1. 首趟保底对任意地图生效（`L.resolveExp` 的 `first`）。
2. 引导首张结算卡的“再去一次”使引导停滞。
3. 修为圆满时在外，修为封顶浪费且无提示。
4. `closeModal` 后 120ms 弹下一窗，截走点击。
5. 人在历练时提示去打首领。
6. 第一届论道可从第 100 名跳到第 55 名，绕过慕容雪。
7. 三宗争徒的高亮按钮是“暂不入宗”。
8. `SPEEDS = [1, 2, 4, 0]`，索引 3 是暂停；`guide_test.js` 里的 `setSpeed(4)` 越界。
9. 筑基瞬间三条成就横幅叠在主角身上。
10. 第一世洗髓丹永远显示“灵根已至巅峰”。
11. 破境丹只进不出（丹炉被动产出）。
